# news-watcher

토큰·LLM 없이 동작하는 뉴스 감시기입니다. 표준 라이브러리만 쓰는 Python으로 약 31개 뉴스 소스(RSS, Hacker News, Reddit, Binance 공지 등)를 폴링해서 규칙 기반으로 점수를 매기고, 중복을 묶은 뒤 '속보'급 기사를 기록합니다.

## 동작 방식
- **GitHub Actions**(`.github/workflows/watch.yml`)가 15분마다(cron `7,22,37,52 * * * *`, UTC) 실행됩니다. 공개 저장소라서 비용은 $0입니다.
- 실행 순서: `state.py load`로 `state/state.jsonl`에서 SQLite DB를 복원합니다 → `watcher.py`로 한 주기를 실행합니다 → `state.py dump`로 정리한 뒤 다시 저장합니다 → 바뀐 내용이 있을 때만 `github-actions[bot]` 이름으로 커밋하고 푸시합니다.
- 저장소 크기를 작게 유지하려고, 기사 상태는 최근 **3일**, `state/breaking.log`는 최근 **7일**만 남깁니다. `candidates.jsonl`와 실행 로그는 커밋하지 않습니다(로그는 각 Actions 실행 로그에서 볼 수 있습니다).
- 실패한 소스는 기존과 같이 백오프됩니다(연속 실패 시 몇 주기 건너뜀).
- `fire_webhook()`은 `WEBHOOK_URL` 환경변수가 없으면 아무것도 하지 않습니다. 현재 시크릿을 설정하지 않았으므로 **외부로 메시지를 보내지 않습니다.**

## 결과 보기
- 속보 기록: 저장소의 `state/breaking.log`(한 줄에 JSON 하나)를 보면 됩니다.
- 요약 리포트(로컬):
  ```bash
  git pull
  python3 state.py load          # state/state.jsonl -> data/watcher.db
  python3 report.py --hours 24   # --topic crypto, --queue breaking 등
  ```
- 실행별 소스 성공/실패: Actions 탭에서 각 실행의 "Run watcher" 단계 로그를 보면 됩니다.

## 거르기 규칙

아침 브리핑이 읽는 형식은 그대로입니다. `state/breaking.log`의 JSON 한 줄, `state/state.jsonl`의 기사 행, `report.py` 요약이 같은 자리에 남습니다. 달라진 점은 **무엇을 남기느냐**입니다. 주제 `other`(네 분야에 안 걸리는 기사)는 더 이상 저장하지 않습니다. `report.py`는 원래도 `other`를 빼므로 출력 모양은 같습니다.

한 주기에서 기사는 아래 순서로 걸러집니다.

- **제목 노이즈.** 부고·인사·게시판·로또·날씨·시황 칼럼·가격 예측·거래대금 순위·추모처럼 브리핑에 넣을 이유가 없는 제목은 점수 내기 전에 버립니다. 꼭지 표시는 괄호 안의 일반 표지입니다. `[칼럼]` `[사설]` `[기고]` `[시론]` `[오피니언]` `[전망]` `[초점]`, 예능 괄호 `[예능]` `[연예]` `[드라마]` `[오락]`, URL 경로 `/opinion/`·`/column/`을 버립니다. 예금금리·적금금리·금리표처럼 금리표 제목도 버립니다. `전망`이 괄호 표지가 아니면 남깁니다. 수출·실적 기사의 전망까지 같이 빠지기 때문입니다. 지역 이름, 인명, 인용된 프로그램 이름은 그 단어만으로 버리지 않습니다.
- **한글은 부분 문자열이 아닙니다.** `유가`가 `유가족`·`이유가`·`액화석유가스`에 걸리지 않고, `금리`가 길 이름 `금리단길`에 걸리지 않습니다. `국제유가`·`금리인하`처럼 그 단어가 맞는 복합어는 그대로 맞습니다.
- **약한 단어만으로는 주제를 만들지 않습니다.** `AI`, `로봇`, `주가`, `급락`, `코인`, `crash`, `대통령`처럼 혼자서는 어디든 붙는 단어는, 같은 제목에 더 구체적인 단어가 있거나 `[속보]`가 있을 때만 남깁니다. 그래서 "AI 골프대회"나 지역 업무협약 기사는 빠지고, 인천공항 장애 속보는 남습니다.
- **정치는 한미 범위만.** 트럼프·이재명·북한·국회·중간선거처럼 한미 정치의 닻이 있어야 합니다. `대통령`만 있는 한국어 기사는 남기되, 후티·폴란드 헌재·시진핑·독일처럼 미리 둔 제3국 표지가 있는 제목은 버립니다. `헌법재판소`나 `대통령`만으로는 그 제3국 기사를 살리지 않습니다. 한국 순방·방한·정상회담이 외국을 언급하면 남깁니다. 사람 이름을 새로 표지에 넣지는 않습니다.
- **같은 사건은 한 줄.** 창은 24시간입니다. 제목의 글자 3-gram이 크게 겹치거나 내용 단어의 Jaccard가 높으면 한 줄로 합칩니다. 그보다 덜 닮은 제목은, 서로 다른 매체가 같은 고유명(영문 대문자 토큰, 또는 일반 뉴스 단어가 아닌 3–8자 한글 토큰)을 나눠 갖고 그 이름이 창 안에서 이미 여러 줄에 퍼져 있지 않을 때만 합칩니다. 이름 목록은 없습니다. 합칠 때마다 그 줄의 이름은 교집합만 남깁니다. 점수가 더 높은 제목이 그 줄의 제목과 링크로 바뀌고, `url_norm`은 처음 본 주소 그대로입니다. 보상·사망·소송·ETF 유출처럼 새 사실이면 원래 사건과 합치지 않습니다. 삼성 회동과 SK 회동, 해킹 기사와 트럼프의 반응도 따로 둡니다. 24시간이 지난 재탕은 새 줄입니다.
- **속보 기준.** 점수 9 이상, 발행 후 3시간 이내, 그리고 키워드 점수가 있거나 가격이 5% 이상 움직인 경우만 `breaking.log`에 적습니다. 출처가 여러 개라는 이유만으로 약한 단어가 속보가 되지는 않습니다.

`python3 test_filters.py`가 위 규칙의 회귀 사례를 확인합니다.

## 일시정지 / 재개
- Actions 탭 → `news-watch` → `...` → **Disable workflow**를 누르면 멈추고, **Enable workflow**를 누르면 다시 돌아갑니다.
- 또는 `gh workflow disable news-watch` / `gh workflow enable news-watch` 명령을 씁니다.
- 수동 실행: `gh workflow run news-watch`

## 주의: 60일 비활성 규칙
GitHub는 공개 저장소에서 **60일 동안 저장소 활동이 없으면** 예약(schedule) 워크플로를 자동으로 비활성화합니다. 이 워크플로는 상태가 바뀔 때마다 커밋하기 때문에 보통은 계속 활성 상태로 유지됩니다. 그래도 멈췄다면 Actions 탭에서 다시 Enable 하면 됩니다.
